## Дәрістің мақсаты

Оқушы:

- бинарлық іздеудің міндетті шарты — монотонды қасиетті — түсіндіреді;
- іздеу аралығын екіге бөледі;
- left, right, mid инвариантын сақтайды;
- бүтін жауаптың ең кішісін немесе ең үлкенін іздейді;
- жауап бойынша бинарлық іздеуді қолданады;
- нақты мәнді eps дәлдігімен табады;
- O(log N) артықшылығын сызықтық іздеумен салыстырады.

## 1. Бинарлық іздеу идеясы

Бинарлық іздеу іздеу аралығын әр қадамда екіге қысқартады. Сондықтан N мүмкіндіктің ішінен жауапты табу шамамен log2(N) тексеруді қажет етеді.

Бірақ кез келген есепке бинарлық іздеу қолданылмайды. Міндетті шарт:

> жауапқа қатысты тексеру false false false true true true немесе true true true false false false тәртібімен өзгеруі керек.

Бұл — монотонды қасиет.

### Қарапайым мысал

1 мен 100 аралығындағы сан жасырылды. «Жасырын сан x-тен үлкен бе?» деген сұрақ қоямыз.

- «Иә» болса, сол жақ шекараны ортадан кейін жылжытамыз;
- «Жоқ» болса, оң жақ шекараны ортаға дейін қысқартамыз.

100 санды бір-бірлеп тексерудің орнына 7 сұрақ жеткілікті, себебі 2^7 > 100.

## 2. Бүтін бинарлық іздеудің шаблоны

Ең кіші x мәнін табайық: good(x) функциясы x жеткілікті үлкен болғанда true болсын.

```cpp
long long left = low;
long long right = high;

while (left < right) {
    long long mid = left + (right - left) / 2;

    if (good(mid)) {
        right = mid;
    } else {
        left = mid + 1;
    }
}

long long answer = left;
```

### Инвариант

Циклдің әр айналымында:

- жауап [left, right] аралығында қалады;
- right — жарамды жауап болуы мүмкін;
- left-тен кіші мәндер good шартын қанағаттандырмайды;
- цикл аяқталғанда left == right, демек бір кандидат қалады.

mid = left + (right - left) / 2 формасы үлкен сандарда left + right толып кетпеуі үшін қолданылады.

## 3. Шекараны таңдау

Бинарлық іздеудің ең жиі қатесі — low және high шекараларын дәлелдемей қою.

Шекараны таңдағанда:

1. төменгі шекарада жауап жоқ немесе good(low) белгілі болуы керек;
2. жоғарғы шекарада кемінде бір жарамды жауап болуы керек;
3. good(high) = true екенін дәлелдеу керек;
4. цикл соңында жауаптың қай шекарада сақталатынын білу керек.

Егер жоғарғы шекара белгісіз болса, оны екі еселеп табуға болады:

```cpp
long long high = 1;
while (!good(high)) {
    high *= 2;
}
```

## 4. Жауап бойынша бинарлық іздеу: «Ксерокопии»

Екі ксерокс бір парақты сәйкесінше a және b уақытта шығарады. n көшірмені ең аз уақытта жасау керек.

Белгілі бір t уақытта қанша парақ шығатынын тексереміз:

`copies(t) = t / a + t / b`

Егер copies(t) >= n болса, t жеткілікті. Уақыт артқан сайын көшірме саны кемімейді, яғни қасиет монотонды.

### Жарамдылық функциясы

```cpp
bool can(long long time, long long n, long long a, long long b) {
    return time / a + time / b >= n;
}
```

Үлкен шектеулерде қосынды толып кетуі мүмкін. Қауіпсіз нұсқа:

```cpp
bool can(long long time, long long n, long long a, long long b) {
    __int128 copies = (__int128)(time / a) + time / b;
    return copies >= n;
}
```

### Толық идея

1. low = 0, high — міндетті түрде жеткілікті үлкен уақыт.
2. mid уақытын тексеру.
3. Жеткілікті болса, оң жақты қысқарту.
4. Жеткіліксіз болса, сол жақты жылжыту.
5. low == high болғанда ең аз уақытты шығару.

## 5. Нақты бинарлық іздеу

Нақты жауапты дәл табу мүмкін болмаған жағдайда қателік шегін алдын ала белгілейміз:

```cpp
double left = 0.0;
double right = max(1.0, a);
const double eps = 1e-7;

while (right - left > eps) {
    double mid = (left + right) / 2.0;

    if (mid * mid < a) {
        left = mid;
    } else {
        right = mid;
    }
}

cout << fixed << setprecision(6) << (left + right) / 2.0;
```

Бұл код sqrt(a) мәнін түбір функциясын қолданбай жуықтайды. Мұнда mid * mid < a тексеруі монотонды.

### Нақты бинарлық іздеуде ескерілетіндер

- тоқтау шарты right - left > eps;
- eps есептің талап еткен дәлдігінен кіші болуы керек;
- жауап ретінде left, right немесе ортасын шығару шартқа байланысты;
- double-мен left == right деп тексеруге болмайды.

## 6. Бинарлық іздеу мен sort айырмасы

Сұрыпталған массивтен нақты элементті іздеу үшін стандартты кітапхана функцияларын да қолдануға болады:

```cpp
sort(a.begin(), a.end());
bool found = binary_search(a.begin(), a.end(), x);
```

Бірақ бұл тақырыптағы маңызды дағды — дайын функцияны шақыру емес, іздеу инвариантын түсіну. Жауап бойынша іздеу кезінде массив те, дайын тізім де болмауы мүмкін.

## 8. «Угадай число» арқылы түсіндіру

Оқушыларға алдымен кодсыз ойын ойнатылады:

1. Бір оқушы 1–100 аралығында сан ойлайды.
2. Екіншісі ортадағы санды атайды.
3. Жауапқа қарай диапазонның бір жартысын өшіреді.
4. Қалған диапазонды тақтаға белгілейді.

Содан кейін алгоритм кодқа көшіріледі:

```cpp
int left = 1;
int right = 100;

while (left < right) {
    int mid = left + (right - left) / 2;
    // secret > mid болса: left = mid + 1
    // әйтпесе: right = mid
}

cout << left;
```

Бұл мысалда ask(mid) орнына оқушының жауабы тұрады. ACMP-те интерактивті емес есеп болса, ask функциясын есептің өзіндегі тексеру функциясы алмастырады.

## 9. Қате кодты талдау

### Қате 1: жарамсыздықта right = mid - 1 қолдану

Бұл шаблон кейбір іздеу түріне жарайды, бірақ «ең бірінші true» шаблонында right = mid қажет. Шекараның мағынасы анықталмай тұрып формуланы көшірмейміз.

### Қате 2: left = mid

Егер mid == left болуы мүмкін болса, цикл тоқтамай қалады. left = mid + 1 прогресті міндетті түрде қамтамасыз етеді.

### Қате 3: монотондық дәлелденбеген

Егер good(x) бірде true, бірде false болып ауыса берсе, бинарлық іздеу дұрыс емес. Алдымен шарттың бір бағытта өзгеретінін дәлелде.

### Қате 4: нақты мәнді теңдікпен тексеру

Нақты бинарлық іздеуде left == right емес, аралық ені eps арқылы тексеріледі.
