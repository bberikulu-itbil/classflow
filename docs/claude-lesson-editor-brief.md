# ClassFlow — дәріс слайдын өңдеу модуліне арналған Claude брифі

Бұл құжатты Claude-қа ClassFlow жобасындағы дәріс редакторын әрі қарай жобалау және іске асыру үшін беруге болады.

## 1. Жоба контексті

Жоба: [ClassFlow](https://github.com/bberikulu-itbil/classflow)

ClassFlow — мұғалімге курс, модуль, дайын дәріс, сабақ өткізілімі, тапсырма және бағалауды басқаруға арналған сынып платформасы.

Негізгі иерархия:

```text
Курс
└── Модуль
    └── Дәріс
        └── Беттер
            └── Секциялар / блоктар / элементтер
```

Маңызды терминдер:

- **Курс** — пән немесе сынып деңгейі бойынша толық оқу бағдарламасы.
- **Модуль** — курстың тақырыптық бөлігі.
- **Дәріс** — сабаққа алдын ала дайындалған, толық оқу материалдарымен қамтылған сабақ үлгісі.
- **Сабақ өткізілімі** — дәрісті нақты сыныпта нақты уақытта өткізу оқиғасы.
- **Бет** — дәрістің оқушыға көрсетілетін бір мазмұндық бөлігі.
- **Бет типі** — беттің қалай көрсетілетінін және қалай әрекет ететінін анықтайды.
- **Бет үлгісі** — жаңа бет жасалған кездегі бастапқы орналасу мен мазмұн қаңқасы.
- **Блок / элемент** — бет ішіндегі нақты мазмұн: мәтін, сурет, код, тапсырма және т.б.

Жоғарғы мәзірде мына бөлімдер ғана болуы керек:

- `Модульдер`
- `Курстар`
- `КТП`
- `Ортақ кітапхана`

`Менің сабақтарым`, `Сабақ редакторы`, `Жоспарлар` жоғарғы мәзірде жеке бөлім ретінде болмауы керек.

## 2. Қазіргі іске асқан функционал

Қазіргі кодта:

- `Модульдер` экранында модульді ашқанда дәрістер тізімі көрсетіледі.
- Әр дәрістің жанында `Бастау` және `Өңдеу` батырмалары бар.
- `Бастау` таңдалған сыныппен live-сабақты бастайды.
- Сынып таңдалмаса, `Бастау` disabled күйде қалады және `Алдымен сыныпты таңдаңыз` деген түсіндірме көрсетеді.
- `Өңдеу` `#edit/<lessonId>` маршрутына апарады.
- Модуль ішіндегі `＋ Дәріс жасау` `#edit/new?module=<moduleId>` маршрутына апарады.
- Дәріс редакторында екі режим бар:
  - `Қолмен жасау`
  - `ЖИ арқылы жасау`
- Негізгі ақпарат өрістері:
  - дәріс атауы;
  - пән;
  - сынып;
  - ұзақтығы;
  - қысқаша сипаттама;
  - оқу мақсаттары.
- Дәріс құрылымы `slides[]` массиві арқылы сақталады.
- Әр `slides[]` объектісіне жаңа қосымша өрістер енгізілді:
  - `pageType`;
  - `templateId`.
- Ескі дәрістерде бұл өрістер болмаса, олар автоматты түрде типке бейімделеді.
- Техникалық JSON редакторы `Толық құрылым және техникалық өрістер` бөлімінің ішінде жасырылған.
- ЖИ жасаған дәріс автоматты түрде жарияланбайды, алдымен мұғалім тексереді.

Қазіргі маңызды файлдар:

- `src/components/LessonEditorView.tsx` — дәріс редакторы;
- `src/components/Widgets.tsx` — слайдтарды және ұзын беттерді көрсету;
- `src/components/StudentSessionView.tsx` — оқушы көрінісі;
- `src/components/RemoteView.tsx` — мұғалімнің сыныпты басқару көрінісі;
- `src/curriculum/Views.tsx` — модульдер мен дәрістер тізімі;
- `src/curriculum/store.ts` — модуль/дәріс құрылымының деректері;
- `src/hw/supaApi.ts` — үй тапсырмасына код слайдтарын беру;
- `docs/lesson-architecture.md` — өнім архитектурасы;
- `docs/kbo-1-lectures-3-5.md` — KBO-1 дәрістерінің мазмұны.

## 3. Негізгі мақсат

Дәріс слайдын өңдеуді Canva тәрізді жеңіл интерфейспен жасау, бірақ ClassFlow-тың педагогикалық құрылымын сақтау.

Мұғалім:

1. дәріс жасайды немесе ЖИ арқылы нобай алады;
2. дәріске беттер қосады;
3. әр бетке бет типін таңдайды;
4. сол типке арналған үлгіні таңдайды;
5. бет ішіндегі блоктарды өңдейді;
6. алдын ала қарайды;
7. тексеріп болған соң жариялайды немесе сабақта бастайды.

Бет типін және үлгіні бір ұғымға біріктірмеу керек:

```text
Бет типі = қалай көрсетіледі және қалай жұмыс істейді
Бет үлгісі = бастапқы композиция
Элемент = нақты мазмұн
```

## 4. Бет типтері

### 4.1 Слайд беті

Ішкі атауы: `slide`

Мақсаты: презентация кезінде көрсетуге арналған 16:9 кадр.

Ерекшеліктері:

- 16:9 канва;
- элементтерді еркін орналастыру;
- `x`, `y`, `width`, `height` координаталары;
- фон, түстер, шрифт және туралау баптаулары;
- слайдтар тізімі немесе filmstrip;
- мұғалім көрсететін презентация режимі;
- keyboard navigation: `ArrowLeft`, `ArrowRight`;
- алдын ала қарау және толық экран режимі.

### 4.2 Ұзын бет

Ішкі атауы: `scroll`

Мақсаты: төмен қарай сырғитын, мақалаға ұқсас оқу беті.

Бұл жай ғана ұзын слайд емес. Ол секциялардан тұратын responsive оқу беті болуы керек.

Ерекшеліктері:

- тік сырғыту;
- контенттің максималды ені шамамен 760–900 px;
- сол жақта секциялар жоспары немесе якорь тізімі;
- ортасында оқу беті;
- оң жақта таңдалған секцияның қасиеттері;
- секцияларды жоғары-төмен жылжыту;
- әр секцияға якорь ID беру;
- мәтін, сурет, код, формула және тапсырманы бір ағынға біріктіру;
- responsive mobile layout;
- негізгі реттілік `order` арқылы анықталады, абсолютті `x/y` координаталары қолданылмайды.

Ұзын бетке мысал:

```text
Hero / тақырып
├── 1. Негізгі идея
├── 2. Қадамдық түсіндіру
├── 3. Код мысалы
├── 4. Өзің тексер
└── Қорытынды
```

### 4.3 Интерактивті бет

Ішкі атауы: `interactive`

Мақсаты: оқушыдан әрекет немесе жауап алу.

Ерекшеліктері:

- жауап енгізу;
- бір немесе бірнеше нұсқа таңдау;
- код жіберу;
- автоматты тексеру;
- кері байланыс;
- ұпай және әрекет күйі;
- тапсырманы ашу/жабу;
- жауаптарды мұғалім көрінісінде жинау.

### 4.4 Тексеру беті

Бірінші нұсқада жеке техникалық бет типі ретінде енгізбеу керек. Ол `interactive` типінің арнайы үлгілері арқылы жасалады.

Кейін бөлек типке айналдыруға болады, егер оған:

- жеке бағалау алгоритмі;
- уақыт шектеуі;
- бірнеше әрекет мүмкіндігі;
- нәтиже беті;
- талдау және статистика

сияқты бөлек логика қажет болса.

## 5. Бет үлгілері

Үлгілер бет типіне қарай сүзгіленуі керек. Слайд үлгісін ұзын бетке немесе интерактивті бетке араластырмау керек.

### Слайд бетінің үлгілері

| `templateId` | Атауы | Негізгі блок |
|---|---|---|
| `title` | Титул | Тақырып, ішкі тақырып |
| `explanation` | Түсіндіру | Мәтін және негізгі ойлар |
| `code-example` | Код мысалы | Код және түсіндірме |
| `comparison` | Салыстыру | Екі ұғымды қатар көрсету |
| `image-text` | Мәтін + сурет | Визуал және түсіндірме |
| `practice` | Практика | Тапсырмаға кіріспе |
| `summary` | Қорытынды | Негізгі ойлар және келесі қадам |

### Ұзын бет үлгілері

| `templateId` | Атауы | Қолданылуы |
|---|---|---|
| `theory` | Теориялық түсіндіру | Ұғым, анықтама, мысал |
| `worked-example` | Қадамдық мысал | Есепті шешу жолы |
| `code-guide` | Код + түсіндірме | Кодты секциялармен ашу |
| `case-study` | Мысал арқылы оқу | Бір есепті толық талдау |
| `task-flow` | Тапсырмаға апаратын бет | Түсіндіру → әрекет |
| `summary` | Қорытынды | Қысқаша қайталау |

### Интерактивті бет үлгілері

| `templateId` | Атауы | Қолданылуы |
|---|---|---|
| `single-choice` | Бір жауап | Бір дұрыс нұсқа |
| `multi-choice` | Бірнеше жауап | Бірнеше дұрыс нұсқа |
| `short-answer` | Қысқа жауап | Мәтіндік жауап |

| `matching` | Сәйкестендіру | Екі бағанды сәйкестендіру |

## 8. Жаңа бет жасау сценарийі

Мұғалім `＋ Бет қосу` батырмасын басады.

1. `Бет типін таңдаңыз`:
   - Слайд беті;
   - Ұзын бет;
   - Интерактивті бет.
2. Таңдалған типке сәйкес үлгілер көрсетіледі.
3. Мұғалім үлгіні таңдайды.
4. Бет атауын енгізеді.
5. `Бетті жасау` батырмасын басады.
6. Жаңа бет дәріс құрылымына қосылады.
7. Мұғалім мазмұнды редакторда өңдейді.

Бет типін кейін өзгертуге болады, бірақ ескерту керек:

> Бет типін өзгерту кейбір орналасу параметрлерін өзгертуі мүмкін. Өзгерту алдында нобай сақталады.

Слайдтан ұзын бетке ауыстырғанда:

- `x/y` координаталары сақталмайды немесе секция ретіне түрленеді;
- мәтін және код сақталады;
- күрделі фигуралар қайта орналастыруды қажет етуі мүмкін.

## 9. Қолмен жасау және ЖИ арқылы жасау

Екі бөлек редактор жасалмауы керек. Екеуі бір дәріс редакторына әкелуі керек.

```text
Қолмен жасау ──┐
                ├── Бір дәріс редакторы ──> Алдын ала қарау ──> Тексеру ──> Жариялау
ЖИ арқылы жасау ┘
```

### ЖИ формасы

Міндетті өрістер:

- пән;
- модуль;
- дәріс тақырыбы;
- сынып;
- тіл;
- ұзақтығы;
- оқу мақсаты.

Қосымша өрістер:

- бет типтерінің қалаған арақатынасы;
- слайд саны;
- ұзын бет керек пе;
- тапсырмалар саны;
- бағалау түрі;
- үй жұмысы керек пе;
- мұғалімнің арнайы нұсқауы;
- мұғалім файлдары.

### ЖИ кезеңдері

1. ЖИ қысқа дәріс жоспарын ұсынады.
2. Мұғалім жоспарды қабылдайды немесе өзгертеді.
3. ЖИ беттерді типтерге бөліп жасайды.
4. Әр бетке үлгі және блоктар тағайындалады.
5. Мұғалім әр бетті жеке өңдейді.
6. ЖИ тексеру және қайта жазу әрекеттерін ұсынады.
7. Мұғалім preview жасайды.
8. Тек тексерілген дәріс жарияланады.

### Блок деңгейіндегі ЖИ әрекеттері

- `Қайта жазу`;
- `Қысқарту`;
- `Кеңейту`;
- `Қарапайым тілге ауыстыру`;
- `Сынып деңгейіне бейімдеу`;
- `Кодты түсіндіру`;
- `Тапсырма қосу`;
- `Жауап үлгісін жасау`;
- `Оқу мақсатына сәйкестігін тексеру`.

ЖИ нәтижесі автоматты түрде жарияланбауы керек.

## 10. Ұсынылатын деректер моделі

### Lecture

```ts
type Lecture = {
  id: string;
```

### Қазіргі форматпен үйлесімділік

Қазіргі production кодта `cf_lessons.slides` қолданылады. Бірден database migration жасауға асықпау керек.

Аралық кезеңде:

```ts
slides: Array<LegacySlide & {
  pageType?: 'slide' | 'scroll' | 'interactive';
  templateId?: string;
}>
```

Ескі объектілер үшін:

- `title` → `pageType: 'slide'`, `templateId: 'title'`;
- `content` → `pageType: 'slide'` немесе таңдалған үлгіге қарай `scroll`;
- `quiz`, `task`, `matching`, `flashcards` → `pageType: 'interactive'`;
- `code` → әдепкіде `slide`, ал `code-task` үлгісінде `interactive`.

Толық `pages[]` миграциясы жеке кезең ретінде жасалады және барлық оқушы/мұғалім көріністері тексерілгеннен кейін орындалады.

## 11. KBO-1 мазмұны

Негізгі материал: `docs/kbo-1-lectures-3-5.md`.

Пән: `Информатика олимпиадасы`

Модуль: `KBO-1`

Сынып: `7-сынып`

Дәрістер:

1. **Дәріс 3: `vector`**
   - vector мен кәдімгі массив айырмасы;
   - `push_back`, `pop_back`, `size`;
   - индекс және range-based `for`;
   - оң/жұп сандарды жинау;
   - олимпиадалық практика.
2. **Дәріс 4: `sort`, `min/max`, `pow`, `abs`, `gcd`**
   - сұрыптау;
   - минимум/максимум;
   - модуль;
   - дәрежеге шығару;
   - ең үлкен ортақ бөлгіш;
   - аралас есептер.
3. **Дәріс 5: `prefix sum`**
   - prefix массиві;
   - `pref[i + 1] = pref[i] + a[i]`;
   - аралық қосынды;
   - `sum(l, r) = pref[r + 1] - pref[l]`;
   - `O(n)` алдын ала есептеу және `O(1)` сұраныс.

Ұсынылатын беттер мысалы:

```text
1. Титул — Слайд беті / title
2. Оқу мақсаты — Слайд беті / explanation
3. Негізгі идея — Ұзын бет / theory
4. Код мысалы — Ұзын бет / code-guide
5. Қадамдық талдау — Ұзын бет / worked-example
6. Өзің тексер — Интерактивті бет / code-task
7. Қорытынды тест — Интерактивті бет / single-choice
```

## 12. Сапа және қолжетімділік талаптары

- Негізгі интерфейс raw JSON-ға тәуелді болмауы керек.
- JSON тек `Толық құрылым` ішінде қосымша деңгейде қалуы керек.
- Әр негізгі әрекет native button немесе link болуы керек.
- Әр input-та түсінікті label және `aria-label` болуы керек.
- Пернетақта арқылы беттер арасында жүру мүмкіндігі болуы керек.
- Mobile экранда панельдер бір бағанға жиналуы керек.
- Ұзын бетте мәтін ені оқуға ыңғайлы болуы керек.
- Бетті өшіру алдында confirmation қажет.
- Автоматты сақтау және нобай күйі болуы керек.
- ЖИ контенті жарияланбай тұрып міндетті preview/check кезеңінен өтуі керек.
- Күрделі layout түрлендіру кезінде мұғалімге ескерту көрсетілуі керек.

## 13. Acceptance criteria

Функция дайын деп есептеледі, егер:

1. Модуль ішіндегі дәрісте `Өңдеу` батырмасы редакторды ашады.
2. `＋ Бет қосу` бет типін таңдауды ашады.
3. Әр бет типінде тек өз үлгілері көрсетіледі.
4. `Ұзын бет` таңдалса, бет төмен сырғитын оқу preview ретінде көрсетіледі.
5. Слайд беті 16:9 канва ретінде көрсетіледі.
6. Интерактивті бетте жауап және бағалау параметрлері бар.
7. Бет үлгісін ауыстырғанда бет типі өзгермейді.
8. Бет типін ауыстырғанда ықтимал layout өзгерісі туралы ескерту шығады.
9. Ескі `slides[]` дәрістері ашылып, жоғалмайды.
10. Жаңа `pageType` және `templateId` деректері қайта жүктегеннен кейін сақталады.
11. Оқушы және мұғалім/тақта көріністері `scroll` бетті дұрыс көрсетеді.
12. `scroll` ішіндегі түсіндірме код үй жұмысына автоматты түрде ұсынылмайды.
13. ЖИ нәтижесі нобай болып қалады және қолмен өңделеді.
14. `npm run lint`, `npm run build` және қолданыстағы unit-тесттер өтеді.

## 14. Claude-қа арналған жұмыс тәртібі

Мына ережелерді сақта:
